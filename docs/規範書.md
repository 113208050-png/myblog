## 3. 內容規範

### 3.1 文章開頭設定（front matter）

```markdown
---
title: "文章標題"
date: 2026-10-16
draft: true
categories: ["AI 探索"]
tags: ["Claude", "Hugo"]
summary: "一句話摘要"
---
```

- `draft: true` 只在本機預覽看得到；**改成 `false` 才會發佈**
- `categories` 只用兩種：`AI 探索`、`政大日常`
- 第一行必須剛好是 `---`，前面不能有 `\` 或空格

### 3.2 檔名

- 英文小寫加連字號：`how-i-built-my-blog.md`
- 檔名就是網址：`/posts/how-i-built-my-blog/`
- 不用中文和空格

### 3.3 圖片

文章要配圖時改成資料夾：

```
content/posts/how-i-built-my-blog/
├── index.md
└── cover.jpg      ← 內文用 ![說明](cover.jpg)
```

## 4. 設計規範

- 風格：極簡、大量留白、大標題、毛玻璃導覽列、淺灰圓角卡片、藍色連結
- 只模仿設計語言，**不使用 Apple 的 logo、名稱或圖示**
- 所有顏色和圓角都集中在 `custom.css` 最上面的 `:root` 設計 token，換風格只改那裡
- 淺色和深色模式都要能看

| Token | 淺色 | 深色 |
|---|---|---|
| 主要文字 `--ink` | `#1D1D1F` | `#F5F5F7` |
| 次要文字 `--muted` | `#6E6E73` | `#86868B` |
| 卡片底色 `--surface` | `#F5F5F7` | `#1D1D1F` |
| 連結 `--brand` | `#0066CC` | `#2997FF` |
| 頁面底色 `--theme` | `#FFFFFF` | `#000000` |

## 5. 發文流程

1. 雙擊 `新文章.bat`，輸入標題、選分類
2. 在 VS Code 寫內文，`Ctrl + S` 存檔
3. 預覽：`hugo server --buildDrafts`，打開 http://localhost:1313
4. 要發佈時把 `draft: true` 改成 `draft: false`
5. 推上 GitHub（Cloudflare 接好之後會自動更新網站）：

```bash
git add .
git commit -m "新增文章：標題"
git push
```

## 7. 部署（Cloudflare Workers）

帳號已經沒有 Pages 入口，所以改用 Workers 的靜態資源（static assets）發佈。push 到 `main` 後會自動重新部署。

| 設定 | 值 |
|---|---|
| 連接方式 | Continue with GitHub → `113208050-png/myblog` |
| Project name | `bluewind-blog`（**必須和 `wrangler.jsonc` 的 `name` 一致**） |
| Build command | `bash tools/cf-build.sh` |
| Deploy command | `npx wrangler deploy` |
| Preview builds | 開啟 |
| Cloudflare Access | 關閉（打開的話訪客要登入） |

相關檔案：

| 檔案 | 作用 |
|---|---|
| `wrangler.jsonc` | Worker 名稱，以及把 `public/` 當成網站檔案發佈 |
| `tools/cf-build.sh` | 抓主題 submodule、下載 Hugo（預設 0.167.0）、建置網站 |
| `.gitattributes` | 讓 `.sh` 檔固定用 LF 換行，否則 Linux 上執行會出錯 |

升級 Hugo 時：改 `tools/cf-build.sh` 的預設版本，並在本機用同一版本測試。

上線後的待辦：

## 8. Claude 的權限清單

### 8.1 會用到、可以直接做的（屬於這個專案的日常工作）

| 動作 | 用途 | 範圍 |
|---|---|---|
| 讀取檔案 | 了解目前的設定和文章 | 只限 `myblog` 資料夾 |
| 新增、修改檔案 | 改設定、版型、樣式；幫你寫文章草稿 | 只限 `myblog` 資料夾，`themes/` 除外 |
| 執行 `hugo` | 建置、檢查有沒有錯誤 | 本機 |
| 啟動預覽伺服器 | 在瀏覽器窗格看網站長相 | `localhost:1313` |
| `git status` / `diff` / `log` | 查看目前改了什麼 | 本機，唯讀 |

### 8.2 會先問你、你同意才做的

| 動作 | 原因 |
|---|---|
| `git commit` | 會留下永久紀錄 |
| `git push` | 會把內容推上公開網路；需要登入時在你的終端機分頁執行，由你自己登入 |
| 刪除檔案 | 不可復原 |
| 為了測試而建立再刪除暫存檔 | 會動到你的資料夾 |
| 連上外部網路查資料（例如 GitHub API、其他網站） | 會對外送出請求 |
| 安裝軟體（winget 等） | 會改變你的電腦 |
| 讀取 HypeLink 資料 | 你的帳號資料 |
| 寫入 HypeLink（改品牌頁、連結等） | 會改到公開頁面 |

### 8.3 不會做、請你自己操作的

- 輸入密碼、登入任何帳號（GitHub、Cloudflare）
- 註冊帳號
- 改 GitHub repo 的公開或私人設定、刪除 repo
- 在 Cloudflare 後台建立或刪除專案
- `git push --force` 或改寫歷史
- 修改系統或安全性設定

### 8.4 如果想減少確認視窗

可以把 8.1 的指令加進專案的 `.claude/settings.json` 允許清單（例如 `hugo`、`git status`、`git diff`、`git log`），之後執行這些指令就不會每次跳出確認。8.2 和 8.3 的項目建議維持手動確認。
